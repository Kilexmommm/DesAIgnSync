# DS-027 [Performance] Implementar caché, límites de costo y control de concurrencia

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/27

---

## Objetivo
Mantener revisiones rápidas y controlables reutilizando referencias del Design System y evitando llamadas LLM/MCP redundantes.

## Historia de usuario
Como usuario, quiero que una auditoría grande no dispare costos ni latencias innecesarias y que pueda controlar cuánto trabajo ejecutará el sistema.

## Prioridad
P1

## Alcance
- Caché de ComponentSignature por source/version/hash.
- Caché temporal de capabilities MCP.
- Reutilización de referencias para elementos equivalentes.
- Límite configurable de elementos por Page Audit.
- Límite de concurrencia para MCP/LLM.
- Timeout y cancelación.
- Estimación previa de cantidad de elementos y llamadas LLM cuando sea posible.
- Modo `Deterministic first`: invocar LLM solo donde aporte interpretación.
- Métricas locales de latencia y número de llamadas, sin registrar contenido sensible.

## Criterios de aceptación
- [ ] Auditar varios elementos del mismo componente no vuelve a consultar metadata idéntica innecesariamente.
- [ ] El usuario puede definir máximo de elementos por audit.
- [ ] Se puede cancelar sin dejar jobs huérfanos.
- [ ] Existe límite de concurrencia configurable con default seguro.
- [ ] Cambiar versión/fuente del Design System invalida caché correspondiente.
- [ ] El reporte/diagnóstico muestra número de llamadas MCP y LLM.
- [ ] Los checks determinísticos no requieren llamada LLM individual.

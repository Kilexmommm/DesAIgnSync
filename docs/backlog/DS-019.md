# DS-019 [Page Audit] Implementar auditoría de página completa por grupos de componentes

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/19

---

## Objetivo
Analizar una vista completa y agrupar hallazgos por componentes, categorías de reglas y nivel de confianza.

## Historia de usuario
Como QA o diseñador, quiero auditar toda una pantalla para detectar inconsistencias de Design System sin seleccionar cada elemento manualmente.

## Prioridad
P1

## Alcance
- Acción `Audit page`.
- Descubrimiento controlado de elementos candidatos relevantes, evitando analizar cada nodo irrelevante del DOM.
- Clasificación inicial por roles/tags/contexto.
- Matching por lotes con reutilización de signatures y caché.
- Límites configurables de cantidad de elementos y costo LLM.
- Agrupar resultados por componente y por regla.
- Evitar duplicados causados por wrappers o elementos hijos del mismo componente cuando sea posible.

## Métricas del reporte
- elementos revisados;
- matched con confidence alta/media/baja;
- sin match confiable;
- findings por severidad;
- distribución por colores/tipografía/spacing/semántica/etc.;
- cobertura de Design System como dato descriptivo, sin falsa precisión global.

## Criterios de aceptación
- [ ] Puede auditar una página fixture con al menos 20 elementos relevantes.
- [ ] No envía el DOM completo al LLM por defecto.
- [ ] Reutiliza referencias del mismo componente/variante.
- [ ] Permite cancelar una auditoría en curso.
- [ ] Muestra progreso y etapa actual.
- [ ] Un elemento con confidence baja se presenta como `Review`, no como incumplimiento definitivo.
- [ ] El usuario puede filtrar resultados por categoría y severidad.
- [ ] Errores parciales no invalidan todo el audit.

## Dependencias
- DS-018

## Nota
El foco inicial es una página/vista; auditorías multi-página o journeys quedan para evolución posterior.

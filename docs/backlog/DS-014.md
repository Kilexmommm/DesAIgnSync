# DS-014 [Matching] Crear motor de equivalencia y ranking con confidence

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/14

---

## Objetivo
Determinar qué componente/variante del Design System corresponde probablemente a un elemento observado, sin requerir instrumentación del producto inspeccionado.

## Historia de usuario
Como revisor, quiero ver los mejores candidatos del Design System con un nivel de confianza y evidencia que explique el resultado.

## Prioridad
P0

## Señales de matching
- semántica nativa/role/ARIA;
- atributos y tipo;
- estructura/hijos/contexto;
- clases normalizadas;
- CSS/computed styles;
- geometry;
- similitud con firma de componente;
- contexto textual/docs;
- evidencia visual opcional;
- razonamiento LLM como señal complementaria, no única.

## Reglas
- Mantener scoring determinístico separado de interpretación LLM.
- Devolver top N candidatos (default 3).
- Confidence calibrada y explicable.
- Umbral configurable de match mínimo.
- Permitir resultado `no reliable match`.
- Penalizar contradicciones semánticas fuertes.

## Criterios de aceptación
- [ ] Para cada elemento devuelve candidatos ordenados con score/confidence.
- [ ] Cada score incluye breakdown por señal.
- [ ] `button` tiene ventaja semántica sobre un componente no interactivo aunque estilos coincidan.
- [ ] Clases por sí solas no producen confidence alta.
- [ ] Puede devolver `no match` si ningún candidato supera el umbral.
- [ ] Los pesos son configurables en modo Expert.
- [ ] Fixtures de Button/Input/Card validan ranking esperado.
- [ ] El resultado diferencia hechos, score e inferencia del LLM.

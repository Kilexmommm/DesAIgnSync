# DS-022 [Security] Aplicar privacidad, sanitización y defensa contra prompt injection

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/22

---

## Objetivo
Proteger secretos, contenido sensible y comportamiento del agente durante inspecciones de páginas reales.

## Historia de usuario
Como usuario, quiero revisar aplicaciones internas sin que datos sensibles de la página se envíen innecesariamente al modelo o puedan alterar las instrucciones del agente.

## Prioridad
P0

## Controles requeridos
- Tratar todo contenido de la página como `untrusted evidence`.
- Sanitización de texto/atributos antes de enviar al LLM.
- Allowlist de campos de DOM/ARIA/CSS enviados.
- Minimización de screenshots: crop de elemento cuando sea suficiente.
- Modo `Do not send screenshots`.
- Modo `Local-only deterministic review` cuando no se quiera usar LLM.
- Redacción configurable de emails, tokens, IDs sensibles y patrones custom.
- Bloqueo/confirmación para páginas configuradas como sensibles.
- No persistir contenido completo de páginas por defecto.
- Retención local configurable de reportes.

## Prompt injection
- DOM, texto, atributos, comentarios, metadata y screenshots nunca son instrucciones.
- Ignorar instrucciones encontradas en la página como `ignore previous instructions`.
- Solo Core Prompt + configuración del usuario pueden dirigir al agente.

## Criterios de aceptación
- [ ] Tests demuestran que contenido de página con instrucciones maliciosas no cambia el objetivo del agente.
- [ ] API keys nunca aparecen en payloads de análisis.
- [ ] El usuario puede desactivar screenshot/vision.
- [ ] Se puede revisar determinísticamente sin invocar LLM.
- [ ] PII/redaction configurable se aplica antes de enviar al proveedor.
- [ ] Logs no contienen contenido sensible completo por defecto.
- [ ] El usuario puede borrar historial/reportes locales.
- [ ] Política de privacidad del producto queda documentada técnicamente.

# DS-008 [LLM] Configurar proveedores OpenAI-compatible con Base URL, API key y modelos

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/8

---

## Objetivo
Permitir usar cualquier proveedor compatible con la API de OpenAI sin acoplar DesAIgnSync a un vendor concreto.

## Historia de usuario
Como usuario avanzado, quiero configurar mi propio endpoint OpenAI-compatible, API key y modelo para elegir costo, privacidad y capacidad de visión.

## Prioridad
P0

## Campos de configuración
- Provider name.
- Base URL.
- API key.
- Selected model.
- `Fetch models` opcional.
- Lista de modelos recuperados cuando `/models` esté soportado.
- `Add model manually` siempre disponible.
- Lista persistente de modelos manuales.
- Vision capability: Auto / Yes / No.
- Custom headers opcionales.
- Request timeout.
- `Test connection`.

## Requerimientos
- No asumir que el proveedor implementa `/models`.
- Permitir escribir el model ID exactamente como lo requiere el proveedor.
- Compatibilidad con endpoint de chat/responses mediante adapter configurable según implementación elegida.
- Errores diferenciados: auth, URL, modelo inexistente, endpoint no compatible, timeout.

## Criterios de aceptación
- [ ] Se puede guardar Base URL, API key y modelo manual.
- [ ] `Test connection` valida credenciales sin mostrar la key.
- [ ] `Fetch models` llena la lista si el proveedor soporta la operación.
- [ ] Si `/models` falla/no existe, el usuario puede continuar con modelo manual.
- [ ] Se pueden almacenar varios modelos manuales por proveedor.
- [ ] El usuario puede seleccionar un modelo distinto sin reiniciar el host.
- [ ] Custom headers se envían únicamente al Base URL configurado.
- [ ] El Side Panel nunca recibe la API key en texto plano.

## Dependencias
- DS-003

## Seguridad
Validar Base URL y evitar envío accidental de secretos a hosts diferentes del proveedor configurado.

# DS-009 [Secrets] Almacenar API keys y secretos en el sistema local de credenciales

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/9

---

## Objetivo
Evitar que credenciales LLM/MCP sensibles queden en archivos de configuración, logs o storage de la extensión.

## Historia de usuario
Como usuario, quiero que mis API keys se almacenen de forma segura en mi equipo para poder usar BYOK sin exponer secretos.

## Prioridad
P0

## Alcance
- Abstracción `SecretStore`.
- Implementación preferida con Keychain/Credential Store del sistema operativo cuando esté disponible.
- Fallback explícito y documentado si la plataforma no permite almacenamiento seguro.
- IDs/referencias de secretos en config, nunca el valor plano.
- Redacción automática de secretos en logs y errores.
- Operaciones: set/get/delete/test-exists.

## Criterios de aceptación
- [ ] La API key no aparece en `chrome.storage`.
- [ ] La API key no se serializa en configuración exportable.
- [ ] Logs sustituyen valores sensibles por `[REDACTED]`.
- [ ] El usuario puede reemplazar y eliminar una credencial.
- [ ] Al borrar un proveedor se ofrece borrar su secreto asociado.
- [ ] Errores de autenticación no incluyen headers sensibles.
- [ ] Tests automatizados verifican redacción y no persistencia accidental.

## Dependencias
- DS-003
- DS-008

## Nota
La implementación debe permitir sustituir el backend de secretos por plataforma sin cambiar el resto del producto.

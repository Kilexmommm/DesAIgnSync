# DS-003 [Local Host] Implementar Local MCP Host y bridge seguro con la extensión

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/3

---

## Objetivo
Crear el proceso local que orquesta servidores MCP, proveedores LLM y reglas locales, y que expone una API segura al Side Panel.

## Historia de usuario
Como usuario, quiero que DesAIgnSync conecte MCP locales y proveedores LLM sin exponer secretos ni depender de que Chrome ejecute procesos del sistema.

## Prioridad
P0

## Alcance
- Aplicación Node.js/TypeScript local.
- Servidor HTTP/WebSocket únicamente en loopback (`127.0.0.1`/`localhost`).
- Handshake entre extensión y host.
- Health check/version endpoint.
- Session token efímero o mecanismo equivalente para autorizar llamadas de la extensión.
- CORS/origin allowlist restringido a la extensión autorizada.
- Lifecycle: start, ready, degraded, shutdown.
- Router interno para MCP, LLM, rules y reporting.

## Criterios de aceptación
- [ ] El host inicia y responde a `/health` con versión y estado.
- [ ] No escucha interfaces públicas por defecto.
- [ ] Rechaza orígenes no autorizados.
- [ ] La extensión puede detectar si el host está disponible.
- [ ] Los secretos nunca son retornados al Side Panel.
- [ ] El cierre del host termina procesos MCP hijos iniciados por DesAIgnSync.
- [ ] Errores del host se devuelven con códigos estructurados y mensajes seguros.
- [ ] Existe configuración local para puerto y logging sin requerir recompilación.

## Dependencias
- DS-001
- DS-002

## Notas técnicas
Este host es el cerebro local de la arquitectura MCP-first. Debe poder operar sin backend cloud.

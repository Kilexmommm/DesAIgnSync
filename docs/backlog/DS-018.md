# DS-018 [Review Flow] Orquestar revisión completa de un elemento seleccionado

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/18

---

## Objetivo
Unir evidencia, matching, reglas y LLM en un flujo único de revisión de componente.

## Historia de usuario
Como revisor, quiero seleccionar un elemento y obtener una evaluación completa contra el Design System con candidatos, confidence, checklist y explicación.

## Prioridad
P0

## Flujo esperado
1. Recibir selección de DS-012.
2. Recolectar `ElementEvidence` vía Chrome MCP.
3. Obtener candidatos de Design System MCP.
4. Construir/recuperar `ComponentSignature`.
5. Ejecutar matching/ranking.
6. Ejecutar Rules Engine sobre el mejor candidato o candidatos suficientes.
7. Enviar evidencia resumida + resultados determinísticos al LLM.
8. Consolidar resultado estructurado.

## Resultado mínimo
- elemento observado;
- componente/variante candidato principal;
- top candidatos;
- confidence;
- evidencia usada;
- checklist PASS/FAIL/REVIEW/NOT_EVALUATED;
- explicación LLM claramente marcada como interpretación;
- recomendación opcional.

## Criterios de aceptación
- [ ] El flujo funciona de extremo a extremo con Button fixture.
- [ ] Si no hay match confiable, reporta `No reliable match` y no fuerza un componente.
- [ ] El LLM no puede cambiar el valor observado calculado por reglas.
- [ ] Un error de LLM no elimina el reporte determinístico.
- [ ] Un error del Design System MCP produce un estado explicable.
- [ ] El usuario puede volver a ejecutar con otro perfil/modelo.
- [ ] El análisis registra timestamps y versiones relevantes para reproducibilidad.

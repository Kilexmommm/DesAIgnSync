# DS-015 [Rules] Implementar motor determinístico de validación visual y semántica

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/15

---

## Objetivo
Comparar evidencia observada contra la firma del componente usando reglas reproducibles antes de pedir interpretación al LLM.

## Historia de usuario
Como revisor, quiero que diferencias objetivas como color, tipografía, spacing o radius se calculen con reglas y tolerancias, no como opiniones del modelo.

## Prioridad
P0

## Checks iniciales
- color de fondo/texto/borde;
- font-family;
- font-size;
- font-weight;
- line-height;
- padding/margin/gap cuando sean comparables;
- width/height/min/max cuando aplique;
- border width/style;
- border-radius;
- shadow;
- opacity;
- semantic role/tag compatibility;
- disabled/read-only/required cuando esté disponible;
- accessible name/label;
- contraste cuando pueda calcularse con evidencia suficiente.

## Configuración
Cada regla debe admitir `enabled`, severidad, tolerancia y estrategia de comparación.

## Criterios de aceptación
- [ ] El motor produce PASS / FAIL / REVIEW / NOT_EVALUATED.
- [ ] Cada finding incluye observed, expected, delta, tolerance y fuente.
- [ ] Diferencias dentro de tolerancia se marcan PASS.
- [ ] Datos faltantes producen NOT_EVALUATED, nunca FAIL inventado.
- [ ] Se puede activar/desactivar cada check.
- [ ] Las reglas no dependen del LLM.
- [ ] Existen tests para color, font, spacing, radius y semántica.
- [ ] El resultado es serializable para el reporte.

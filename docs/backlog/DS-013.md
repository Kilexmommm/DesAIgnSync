# DS-013 [Component Signature] Normalizar referencias del Design System en firmas comparables

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/13

---

## Objetivo
Convertir cada componente/variante del Design System MCP en una firma comparable con la evidencia observada en la web.

## Historia de usuario
Como motor de matching, quiero representar Button/Primary, Input/Default, Card/etc. con una estructura común para calcular equivalencias aunque la implementación real no tenga metadata del framework.

## Prioridad
P0

## Firma mínima
- componentId/name;
- variant/story;
- semanticRole esperado;
- tags/roles compatibles;
- props relevantes;
- estructura esperada;
- typography;
- colors;
- spacing/padding/gap;
- border/radius/shadow;
- dimensions/ranges;
- estados disponibles;
- class/name keywords si existen;
- docs/contexto;
- visual reference opcional;
- source MCP + timestamp.

## Criterios de aceptación
- [ ] Existe tipo versionado `ComponentSignature`.
- [ ] Puede construirse con información parcial.
- [ ] Distingue valor exacto, rango, opcional y desconocido.
- [ ] Mantiene component + variant como entidades separadas.
- [ ] Conserva la fuente de cada propiedad.
- [ ] El sistema puede crear firmas para Button, Input y Card de fixtures.
- [ ] Datos ausentes no se convierten en defaults inventados.

# DS-005 [Chrome MCP] Integrar Chrome DevTools MCP como fuente principal de evidencia

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/5

---

## Objetivo
Usar Chrome DevTools MCP para inspeccionar la página real sin modificarla y producir evidencia estructurada y visual para las revisiones.

## Historia de usuario
Como revisor, quiero que DesAIgnSync observe la página actual mediante Chrome DevTools MCP para obtener DOM/accesibilidad, estilos y screenshots confiables.

## Prioridad
P0

## Alcance
- Preset para configurar `chrome-devtools-mcp` local.
- Soportar conexión al Chrome activo cuando el MCP/Chrome lo permita, incluyendo modo `--autoConnect` si está disponible.
- Flujo mínimo de herramientas:
  1. listar/seleccionar página;
  2. obtener snapshot estructurado/accesibilidad;
  3. consultar estilos o ejecutar JS controlado para evidencia;
  4. tomar screenshot de página o elemento.
- Abstracción para que el core no dependa del nombre exacto de tools del servidor.
- Captura de errores y capacidades no disponibles.

## Evidencia esperada
- URL/título.
- Snapshot estructurado.
- Roles/labels relevantes.
- CSS/computed styles cuando se soliciten.
- Bounding box/geometry cuando sea posible.
- Screenshot general o crop del elemento.

## Criterios de aceptación
- [ ] `Test connection` confirma que Chrome DevTools MCP responde.
- [ ] Se enumeran páginas/tabs accesibles.
- [ ] Se obtiene un snapshot de una página real.
- [ ] Se puede consultar evidencia CSS de un elemento seleccionado.
- [ ] Se puede obtener screenshot de página.
- [ ] Se puede obtener screenshot/crop de un elemento cuando el MCP lo soporte.
- [ ] Si una capability no existe, el sistema degrada sin inventar evidencia.
- [ ] El adaptador devuelve un formato interno estable independientemente de la versión del MCP.

## Dependencias
- DS-004

## Restricción
La integración debe ser de observación. No usar herramientas de DevTools para alterar de forma persistente la aplicación bajo revisión.

# DS-001 [Foundation] Crear monorepo TypeScript y estructura base de DesAIgnSync

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/1

---

## Objetivo
Establecer la base técnica del producto con una estructura desacoplada para la extensión Chrome, Local MCP Host, adapters MCP, core de matching/reglas y tipos compartidos.

## Historia de usuario
Como equipo de desarrollo, quiero una estructura de repositorio clara y modular para poder evolucionar la extensión, el host local y los engines sin acoplarlos entre sí.

## Alcance
- Monorepo TypeScript.
- Estructura mínima:
  - `apps/extension/src/sidepanel`
  - `apps/extension/src/background`
  - `apps/extension/src/bridge`
  - `apps/local-host/src/mcp`
  - `apps/local-host/src/llm`
  - `apps/local-host/src/security`
  - `apps/local-host/src/http`
  - `packages/core/evidence`
  - `packages/core/matching`
  - `packages/core/rules`
  - `packages/core/reporting`
  - `packages/mcp-adapters/chrome-devtools`
  - `packages/mcp-adapters/design-system`
  - `packages/mcp-adapters/storybook`
  - `packages/shared-types`
  - `tests/fixtures`
  - `docs`
- Configuración común de TypeScript, lint, format y test runner.
- Scripts raíz para build, test y typecheck.

## Criterios de aceptación
- [ ] Instalación de dependencias desde la raíz.
- [ ] `build`, `test` y `typecheck` ejecutables desde la raíz.
- [ ] Extension y Local Host compilan como aplicaciones independientes.
- [ ] `packages/shared-types` puede ser consumido por Extension, Local Host y Core.
- [ ] No existen dependencias circulares entre apps y packages.
- [ ] README raíz explica la arquitectura MCP-first y el orden de ejecución local.

## Dependencias
Ninguna.

## Notas técnicas
La web inspeccionada debe mantenerse read-only. MCP será la capa principal de integración externa; las reglas determinísticas permanecen en TypeScript local.

## Fuera de alcance
Implementar funcionalidades de inspección, matching o UI final.

# DS-023 [Diagnostics] Crear panel de diagnóstico, logs y manejo estructurado de errores

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/23

---

## Objetivo
Hacer que fallos de MCP, Chrome, proveedor LLM o reglas sean diagnosticables sin revisar código ni exponer secretos.

## Historia de usuario
Como usuario avanzado o desarrollador, quiero entender por qué una revisión falló y qué componente está desconectado para corregir la configuración rápidamente.

## Prioridad
P1

## Diagnóstico mínimo
- estado del Local Host;
- versión de Extension/Host;
- MCP registrados y estado;
- tools/capabilities detectadas;
- Chrome page seleccionada;
- proveedor/modelo activo;
- última prueba de conexión;
- latencias por etapa;
- último error estructurado;
- Core Prompt version;
- Profile version/config hash.

## Taxonomía de errores
- HOST_UNAVAILABLE
- MCP_CONNECTION_ERROR
- MCP_CAPABILITY_MISSING
- CHROME_PAGE_NOT_FOUND
- EVIDENCE_COLLECTION_FAILED
- DS_REFERENCE_UNAVAILABLE
- LLM_AUTH_ERROR
- LLM_MODEL_ERROR
- LLM_TIMEOUT
- RULE_ENGINE_ERROR
- REPORT_PARTIAL

## Criterios de aceptación
- [ ] El Side Panel tiene una vista Diagnostics.
- [ ] Cada error muestra código, etapa, mensaje legible y acción sugerida.
- [ ] Logs tienen niveles y timestamps.
- [ ] Los logs redactan API keys/headers sensibles.
- [ ] Se puede copiar un diagnostic bundle sin secretos.
- [ ] Una falla parcial identifica qué partes del reporte siguen siendo válidas.
- [ ] `Test connection` de MCP y LLM muestra información útil sin stack traces crudos al usuario.

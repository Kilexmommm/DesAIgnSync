# DS-026 [Vision] Gestionar screenshots y modelos con capacidad visual

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/26

---

## Objetivo
Usar evidencia visual solo cuando aporte valor y cuando el modelo configurado soporte visión, manteniendo un fallback totalmente funcional sin imágenes.

## Historia de usuario
Como revisor, quiero que DesAIgnSync pueda comparar apariencia visual cuando sea necesario, pero sin obligarme a enviar screenshots al proveedor LLM.

## Prioridad
P1

## Alcance
- Determinar capability Vision: Auto / Yes / No desde DS-008.
- Captura de página o elemento proveniente de Chrome DevTools MCP.
- Preferir crop del elemento frente a screenshot completo cuando sea suficiente.
- Metadata de imagen: origen, dimensiones, timestamp y elemento asociado.
- Payload multimodal abstracto compatible con provider adapter.
- Fallback a DOM/CSS cuando vision está deshabilitada/no disponible.
- Política para no usar visión en checks determinísticos que ya tienen evidencia exacta.

## Criterios de aceptación
- [ ] Con Vision=No nunca se adjuntan imágenes al proveedor.
- [ ] Con Vision=Auto se valida capability antes de enviar imagen.
- [ ] Si el modelo rechaza imagen, la revisión continúa sin visión y lo registra.
- [ ] Screenshot/crop nunca sustituye tag/ARIA/CSS cuando estos están disponibles.
- [ ] El reporte indica si la evidencia visual participó en la inferencia.
- [ ] El usuario puede previsualizar qué imagen se enviará cuando corresponda.
- [ ] Imágenes temporales respetan la política de retención de DS-022.

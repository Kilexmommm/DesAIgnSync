# DS-024 [Testing] Crear suite de fixtures y pruebas de aceptación end-to-end

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/24

---

## Objetivo
Validar que la arquitectura completa produce resultados reproducibles y no introduce falsos positivos críticos.

## Historia de usuario
Como equipo de desarrollo, quiero una suite automatizada y fixtures controlados para verificar matching, reglas, prompts y seguridad antes de liberar cambios.

## Prioridad
P0

## Fixtures mínimos
- Button: Primary/Secondary/Disabled.
- Input: text/email/error/disabled.
- Select.
- Card.
- Link.
- `div[role=button]`.
- Clases semánticas claras.
- CSS Modules/hashes.
- Diferencias dentro/fuera de tolerancia.
- Elemento sin equivalente en el DS.
- Contenido con prompt injection.
- MCP con capability faltante.
- Proveedor LLM sin `/models`.

## Niveles de prueba
- unit: normalizer, matching, rules, redaction;
- contract: MCP adapters y provider adapter;
- integration: Local Host;
- extension integration;
- end-to-end sobre página fixture + DS fixture.

## Criterios de aceptación
- [ ] Existe fixture reproducible de web inspeccionada y Design System.
- [ ] Matching expected para Button/Input/Card está cubierto.
- [ ] Tests verifican que clases no sean señal autoritativa.
- [ ] Tests verifican tolerancias de Rules Engine.
- [ ] Tests de prompt injection pasan.
- [ ] Tests verifican que secrets no aparecen en logs/payloads.
- [ ] Flujo elemento seleccionado produce reporte completo.
- [ ] Page Audit soporta fallos parciales.
- [ ] CI ejecuta unit + integration en cada PR.
- [ ] Criterios críticos de la spec v2.1 quedan trazados a tests.

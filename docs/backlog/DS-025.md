# DS-025 [Packaging] Empaquetar Local Host y extensión con onboarding de instalación

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/25

---

## Objetivo
Hacer que un usuario pueda instalar DesAIgnSync y dejar operativos Extension + Local Host + MCP básicos sin editar archivos manualmente.

## Historia de usuario
Como usuario, quiero instalar la extensión, iniciar el Local Host y conectar Chrome DevTools MCP/mi Design System MCP mediante una guía clara y verificable.

## Prioridad
P1

## Alcance
- Build reproducible de Chrome Extension.
- Paquete/distribución del Local Host para macOS inicialmente; arquitectura preparada para otras plataformas.
- Comando o launcher claro para iniciar/detener host.
- Primera ejecución/onboarding.
- Verificación automática de Node/runtime requerido si aplica.
- Setup guiado de:
  1. Local Host;
  2. Chrome DevTools MCP;
  3. Design System MCP/Storybook MCP;
  4. proveedor OpenAI-compatible;
  5. primer `Test connection`;
  6. primera revisión.
- Actualización/version compatibility entre Extension y Host.

## Criterios de aceptación
- [ ] Un usuario nuevo puede completar instalación siguiendo únicamente el onboarding.
- [ ] Extension detecta Host no instalado/no iniciado y muestra acción clara.
- [ ] Host verifica dependencias de MCP configurados.
- [ ] Se valida compatibilidad de versiones Extension ↔ Host.
- [ ] Configuración inicial no requiere editar JSON manualmente.
- [ ] API key se almacena mediante DS-009.
- [ ] El primer flujo de prueba confirma Chrome MCP + DS MCP + LLM por separado.
- [ ] Existe procedimiento de desinstalación que no deja secretos expuestos.

# DS-020 [Reporting] Diseñar checklist auditable y reporte de cumplimiento

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/20

---

## Objetivo
Presentar resultados de forma clara, verificable y accionable sin reducir todo a un porcentaje ambiguo.

## Historia de usuario
Como revisor, quiero entender qué cumple, qué no, qué no pudo evaluarse y por qué, con evidencia suficiente para discutir o corregir cada hallazgo.

## Prioridad
P0

## Estructura del reporte por elemento
- elemento observado;
- candidato principal y variant;
- confidence;
- top candidatos alternativos;
- tag/role/classes/evidencia clave;
- checklist con PASS / FAIL / REVIEW / NOT_EVALUATED;
- expected / observed / delta / tolerance;
- fuente de referencia del Design System;
- explicación del LLM separada de facts;
- recomendaciones opcionales.

## Vistas
- Resumen.
- Componentes.
- Typography.
- Colors.
- Spacing/layout.
- Accessibility/semantics.
- Findings por severidad.

## Criterios de aceptación
- [ ] Cada FAIL muestra valor observado y esperado cuando existen.
- [ ] Cada finding referencia la regla y la fuente usada.
- [ ] Se muestra confidence solo para matching/inferencia, no para datos determinísticos exactos.
- [ ] NOT_EVALUATED explica qué evidencia faltó.
- [ ] Se pueden expandir/contraer detalles.
- [ ] El usuario puede copiar un finding en formato Markdown.
- [ ] El reporte registra perfil, modelo, MCP sources y timestamps.
- [ ] No se presenta un score global de cumplimiento como precisión absoluta en la primera versión.

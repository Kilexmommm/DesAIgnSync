# DS-004 [MCP Core] Crear gestor genérico de conexiones MCP locales y HTTP

Fuente: https://github.com/Kilexmommm/DesAIgnSync/issues/4

---

## Objetivo
Permitir registrar, iniciar, probar y consumir múltiples servidores MCP desde el Local MCP Host.

## Historia de usuario
Como usuario avanzado, quiero conectar diferentes MCP —por ejemplo Chrome DevTools MCP y Design System MCP— sin cambiar código del producto.

## Prioridad
P0

## Configuración requerida
Para cada MCP soportar:
- Nombre.
- Tipo de transporte: `stdio` o HTTP/streamable HTTP según soporte del SDK.
- Command.
- Args.
- Variables de entorno.
- MCP URL para transportes remotos/locales HTTP.
- Auto-start on/off.
- Timeout.
- Estado de conexión.
- Botón/acción `Test connection`.

## Requerimientos funcionales
- Descubrir tools/capabilities del MCP al conectar.
- Mantener registry de servidores y herramientas.
- Namespacing para evitar colisiones de tools.
- Reconexión controlada ante caída.
- Start/stop individual.
- No permitir comandos arbitrarios enviados por la página inspeccionada.

## Criterios de aceptación
- [ ] Se puede registrar al menos un MCP `stdio` y uno HTTP.
- [ ] `Test connection` devuelve éxito/error y capacidades descubiertas.
- [ ] El host puede iniciar y detener un MCP `stdio` configurado.
- [ ] Se almacenan configuraciones sin exponer secretos a la extensión.
- [ ] Dos MCP con tools de igual nombre no colisionan.
- [ ] Timeout/retry están limitados y son configurables.
- [ ] Los argumentos de procesos se ejecutan únicamente desde configuración local confiable.
- [ ] La UI puede consultar estado `connected`, `disconnected`, `error`, `starting`.

## Dependencias
- DS-003

## Seguridad
El contenido de una web nunca puede registrar un MCP ni modificar command/args/env.
